FOCA 0.23.0 hardens apps against clients that send large bodies or no tokens, and extends the plugin gateway for WES. Request bodies are limited by default (10 MiB, URL-encoded bodies 500 kB) and checked before requests are authenticated, and on operations with bearer tokens that FOCA validates, the token is checked before the body is read. Subjects are always namespaced by their issuer, also with a single trusted issuer, which changes the users that apps and FOCA store; existing deployments keep bare subjects with `namespace: ""` or rewrite them with the new command `foca namespace-subjects`. Plugins of WES gateways get runs in a defined shape, backend lists know WES, FOCA resolves the credentials of backends, and guarded HTTP clients and registry reads can trust private certificate authorities. Patches of specifications can remove keys, the permissions API reports invalid fields, the plugin store limits the size of each namespace, and `$` in patterns matches at the end only. Several changes need action in apps, deployments or clients: see the [migration guide](https://foca.readthedocs.io/en/v0.23.0/migration-0.23/).

## Breaking changes

- Subjects are namespaced by their issuer (`<namespace>|<subject>`) also if only one issuer is trusted: `get_current_subject()`, `get_on_behalf_of_user()`, `namespace_subject()`, the `Principal` of gateway plugins, audit events, stored rules and roles (`user:<namespace>|<subject>`) and owner fields; stored bare users no longer apply, and apps refuse to start while configured rules name bare users. Set `namespace: ""` for the issuer to keep subjects bare, or rewrite stored rules with `foca namespace-subjects` (see [Subjects are always namespaced by issuer](https://foca.readthedocs.io/en/v0.23.0/migration-0.23/#subjects-are-always-namespaced-by-issuer)) (#631, #773)
- Request bodies larger than 10 MiB are rejected with `413` by default (`server.max_content_length`, before without a limit), and URL-encoded bodies larger than 500 kB too (new setting `server.max_form_memory_size`); bodies are checked before requests are authenticated. The configuration template no longer sets `max_content_length: null` (#798, #813)
- On operations that require bearer tokens validated by FOCA, the token is checked before the body is read: anonymous requests with too large bodies get `401` instead of `413`, `before_request` hooks run after this check, and apps that mock Connexion's security handler instead of `foca.security.auth.validate_token` must replace `validate_token` too (#814, #817)
- `null` in patches of specifications removes keys (JSON Merge Patch, RFC 7396) instead of setting values to `null`; files of `path` keep `null` values unless `merge_null_removes: true` is set (#762, #763)
- The permissions API (`/permissions`) rejects invalid rules, identifiers and pages as invalid fields (problem type `invalid-request`, with `errors` and stable codes); its controllers raise `foca.errors.InvalidFieldsProblem` instead of `BadRequest` (#760, #765)
- The plugin store limits each namespace to `max_namespace_size` bytes (by default 16 MiB) and raises `foca.plugins.StoreFullError` beyond it; store backends of their own must accept the new keyword argument `max_size` of `set()` and `increment()`; with a database, sizes are kept in the new collection `plugin_store_sizes` (#552, #774)
- Plugins of WES gateways get runs (`POST /runs`) in one shape, checked after each hook against the new limits `plugins.attachments` (by default 256 files and 32 MiB per run); apps that pass payloads of another shape build them with `foca.plugins.wes.parse_run_request()` (#781, #782)
- A client's backend choice `{"type": "allow", ...}` of identifiers only, none of which names a backend of the gateway, is refused with `400` (`invalid-backends`) by `run.route()`; apps that route only some of their backends pass the others as `known` (#808, #809)
- A `$` in a `pattern` of a request body or parameter matches only at the end of the value, as in ECMA 262, so values with a trailing newline are refused with `400` (`pattern-mismatch`) (#797, #810)

## Features

- Backend lists take WES instances (`type: ga4gh-wes`, API `wes`), `ServiceEntry` has an optional `api_path`, and `BackendList(entries, api=...)` refuses entries of another API's type (#789, #791)
- FOCA resolves the credentials of backends for TES and WES gateways: `ClientCredentialsConfig`, `TokenProvider` (client credentials grant, cached per process), `get_credentials()`, `check_backends()`, and an optional `audience` of `ServiceEntry` (#794, #796)
- `GuardedClient` takes a `ca_bundle` (a file or directory of certificate authorities trusted instead of the public ones); TLS verification can't be turned off (#790, #792)
- `fetch_json()` takes a `ca_bundle`, and registry entries of backend lists a `registry_ca_bundle`, so that registries behind a private certificate authority can be read (#793, #795)
- `foca.plugins.wes` with `parse_run_request()`, `check_run_request()` and `run_request_form()`, and `host.start()` reads the tags of WES runs from the payload (#781, #782)
- `merge_null_removes` of specifications lets merged files of `path` remove keys with `null` (#762, #763)

## Security

- Anonymous clients can no longer make apps parse request bodies of any size: bodies are limited by default and checked before authentication, and bearer tokens validated by FOCA are checked before bodies are read (#798, #813; #814, #817)
- Patterns ending in `$` no longer accept a trailing newline, which let values past request validation that controllers then failed on (#797, #810)
- The semgrep rules shared with the apps find disabled TLS checks in calls on any object (e.g., `session.get(url, verify=False)`) and more ways of decoding JWTs without verification or with algorithms from the token's header (#783, #784)

## Fixes

- Choices of unknown backends are refused with `400` instead of ending without a backend, which apps answered as an outage (#808, #809)

## Documentation

- The [migration guide](https://foca.readthedocs.io/en/v0.23.0/migration-0.23/) covers every change that apps, deployments and clients may have to act on (#631, #773; #798, #813; #814, #817)
- Requests to backends discovered in registries go through `GuardedClient`, which checks the address of each connection, not `BackendSession`, which is for the identity provider and configured backends (#824, #825)
- The migration guide also names the stricter checks of backend lists (entries of another API's type, `audience` without `auth: client_credentials`) and the limit of bare subjects containing `|`, and the API reference lists `InvalidRuleError` (#822, #823)
- The examples no longer import Flask (#753, #764)
- The release commands of the contributing guide run in a worktree at the release commit (#756, #757)
