foca-common 0.6.0 maps the size limit of the namespaces of FOCA 0.23.0's plugin store, and its limits of the files of WES runs. The Ingress now fails to render if ingress-nginx's size limit of request bodies is below the app's. The Ingress can request its certificate from a namespaced cert-manager Issuer. The Celery worker can have a startup probe, and its probes are checked for exactly one handler.

## Breaking changes

- The Ingress fails to render if its annotation `nginx.ingress.kubernetes.io/proxy-body-size` is below the app's limit (`config.server.max_content_length`) or is not a size of ingress-nginx; the error names the value to set (or `0` for no limit). Without the annotation, nothing is checked; the chart still sets none (#785, #787)
- Rendering fails if a probe of the Celery worker (`worker.startupProbe`, `worker.readinessProbe`, `worker.livenessProbe`) or one of its handlers is not a map, or a probe has more than one handler (e.g., `tcpSocket` merged into an app chart's default `exec` probe) or none, which Kubernetes would refuse; this is checked also if the worker is disabled, so leftover values of a disabled worker must be valid too. Set a probe to `null` for none (#786, #788)

## Features

- Gateway apps: `maxNamespaceSize` in the settings of the plugin store (`plugins.defaults.store` and per plugin), as `max_namespace_size` (#552, #774)
- Gateway apps: `maxCount` in the limits of the files of WES runs (`plugins.attachments`), as `max_count` (#781, #782)
- `app-values.schema.json` checks `config.server.max_form_memory_size` of FOCA 0.23.0 and allows `null` for it and `config.server.max_content_length` (no limit); app charts on FOCA 0.23.0 or later whose base config sets no limit set `maxContentLength: 10485760`, FOCA's new default, so that the Ingress check applies; copy `app-values.schema.json` again to use it (#798)
- Celery worker: `worker.startupProbe`, rendered like the readiness and liveness probes; `null` turns off a probe that the app chart sets by default; copy `app-values.schema.json` again to use it and `null` for the worker probes (#786, #788)
- Ingress: `<valuesKey>.ingress.https.issuerKind` requests the certificate from a namespaced cert-manager `Issuer` (`Issuer`, annotation `cert-manager.io/issuer`) instead of a `ClusterIssuer` (`ClusterIssuer`, the default, which renders as before), e.g., on OpenShift clusters where projects can't create cluster-scoped resources; the chart docs describe the OpenShift setup. Other kinds, and annotations naming both a ClusterIssuer and an Issuer, fail to render; copy `app-values.schema.json` again to use it (#811, #820)
