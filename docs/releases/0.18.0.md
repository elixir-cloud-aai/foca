FOCA 0.18.0 adds a plugin engine for gateway apps such as proTES (plugins installed and pinned by operators, per-request pipelines, failover routing, provenance and a plugin test kit), an HTTP client for untrusted URLs guarded against SSRF, opt-in roles (e.g., for an admin mode), settings per trusted issuer and Python 3.15 support, and keeps one cached Casbin enforcer per app instance, so that requests cost about the same with many policy rules as with few. It contains breaking changes: please read [Migrating to 0.18.0](https://foca.readthedocs.io/en/v0.18.0/migration-0.18/) before upgrading.

## Breaking changes

- Access control: each app instance keeps one shared, cached Casbin enforcer, kept up to date via a record of changes (`<collection_name>_changes`); rules changed in the database directly (e.g., with `mongosh`) no longer apply from the next request, but only after `mark_changed()` or a restart; enforcer methods that FOCA's adapter can't store (`update_policy()`, `remove_policies()`) raise `NotImplementedError`; during a rolling update from 0.17, upgrade all instances before changing rules (#450, #454)
- Access control: `get_enforcer()` is removed; use the context manager `locked_enforcer()` (#468, #477)
- Access control and errors: apps refuse to start if `group_mapping` maps groups but no group claim is set, or if `claim_groups` has surrounding whitespace; `exceptions.validation_details` now defaults to `true`, so responses to invalid requests carry the validation reason as `detail` (#467, #475)
- Auth: with several trusted issuers, subjects are namespaced by issuer (`<namespace>|<subject>`, by default the issuer URL), also in policies, resource roles, owners and on-behalf-of users; rules and grants stored for bare subjects no longer apply unless the issuer's `namespace` is set to `""` (#509, #512)
- Auth: trusted issuers can be listed with settings of their own (`namespace`, `audience`, `claim_groups`, `userinfo_claims`), which replace the global settings for their tokens; `security.auth.issuers` is typed `Sequence[str | IssuerConfig]` (use `issuer_urls` for the URLs) (#503, #510, #514)
- Configuration: the top-level `plugins` section is now validated as FOCA's gateway plugin configuration, with unknown keys refused, also in apps that are no gateways; gateway apps refuse the keys of earlier middleware stacks (`middlewares`, `custom.middlewares`) (#486, #496)

## Features

- Gateway plugins: a framework-free plugin engine (`foca.plugins`) for gateway apps, declared with `Foca(gateway=GatewayApp(...))`: plugins from the entry point group `foca.plugins`, allowlisted and pinned in `plugins.available`, run in the phases `request`, `route`, `forward` and `response`, in steps with fallback alternatives, timeouts and `on_failure` (#486, #496)
- Gateway plugins: clients choose presets, own pipelines (off by default) and backends per request in the reserved tags `gateway.pipeline` and `gateway.backends`, within limits, roles and an admin frame (`prepend`, `append`); experimental (#487, #498)
- Gateway plugins: provenance records of each run, with hashes of each plugin's changes and no secrets; optional records of failed runs with a TTL (#488, #499)
- Gateway plugins: typed backend lists for gateway apps (#493, #501), a default failover router `foca.routing.ordered` (#491, #504), gateway tags that record the pipeline, plugins and backend of each task or run (#494, #505), a plugin listing API for clients (`GET /plugins`, `GET /plugins/{plugin_id}`) (#489, #506) and a plugin test kit (`foca.plugins.testing`) with contract checks and fakes (#492, #507)
- Utilities: `GuardedClient` (`foca.utils.http`) sends requests to untrusted URLs with SSRF guards (public addresses only, also after DNS resolution and on connect; redirects not followed; time and size limits); new dependencies `urllib3>=2.6,<3` and `packaging>=23` (#490, #500)
- Access control: opt-in roles (`opt_in_roles`, header `opt_in_header`, default `X-Request-Roles`) that apply only to requests that ask for them, e.g., for an admin mode, with `get_available_opt_in_roles()` and `get_active_opt_in_roles()` (#502, #508)
- Access control: ownership by document field (`set_owner_field()`, `owner_filter()`) for resources that are never shared (#455, #456)
- Configuration: startup checks that warn about settings that likely don't work as intended (e.g., no admins; placeholder service info), and `security.access_control.require_admin` (#459, #466)
- Configuration: public URLs behind proxies (`server.public_url`, `get_public_url()`) and the typed custom configuration (`get_custom_config()`) (#460, #465)
- Errors: request-specific details of validation errors (`exceptions.validation_details`) (#461, #464)
- Deployment: default Gunicorn settings for apps in containers (`foca.gunicorn_config`) (#458, #463)
- Python 3.15 is supported, with images tagged `-py3.15`; the unsuffixed tags stay on Python 3.13 (#448, #457)

## Security

- Gateway plugins: client pipelines are off by default and only accepted from authenticated callers, and the app warns on startup about policy steps of the default pipeline that client pipelines could skip (#518, #526)
- Gateway plugins: the caller (`Principal`) passed to plugins is identified as by access control: on-behalf-of users, the roles of service clients and role rules (#519, #527)
- The SSRF guard rejects IPv6 site-local addresses (`fec0::/10`); the build context of the base image is an allowlist, so local files (e.g., `.env`) can't end up in published images; the petstore-access-control example adds admins via the permissions API (#516, #522)
- The `.dockerignore` files of the examples are allowlists, so that local files stay out of example images (#511, #513)

## Fixes

- Gateway plugins: the plugin listing API works in apps that set a controller for all operations (`add_operation_fields` with `x-openapi-router-controller`) (#515, #521)
- Gateway plugins: gateway settings are bound to their app: a later `Foca(...)` without `gateway=` (e.g., in a Celery worker module) no longer clears them (#517, #525)
- Access control: opt-in roles need no group mapping to them, so that an app's base config can make a role opt-in before its deployments map groups to it; apps warn of opt-in roles that no group is mapped to on startup, and opt-in roles must not be resource roles or start with a subject prefix (#530, #533)
- Releases are published only after their assets are uploaded (#451, #452)
- The petstore chart and the docs use a keep-alive of 100 s, longer than the idle timeouts of common proxies (#469, #478)
