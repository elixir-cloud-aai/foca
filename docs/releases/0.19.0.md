FOCA 0.19.0 gives gateway plugins a shared key-value store (`ctx.store`), e.g., for caches and per-user budgets of third-party APIs, kept in the app's MongoDB database for all processes and replicas, and shows what each plugin stores in the plugin listing. There is no migration guide, as nothing breaks, but operators of gateway apps should read the first two Features bullets before upgrading: gateways with a database create a collection and indexes at startup, and the plugin listing has new required fields.

## Features

- Gateway plugins: a key-value store for plugins (`ctx.store`: `get`, `set`, `delete`, atomic `increment` with limits, and `key_for` to pseudonymize keys), with a namespace per plugin distribution and a TTL on every entry; new settings `plugins.defaults.store` and `plugins.available.<id>.store` (`enabled`, `max_entry_size`, `max_ttl`, by default 30 days). With `db.dbs`, gateway apps keep the entries in the collection `plugin_store` of the app's **first** database (not in the policy database that access control adds for apps without one) and create its indexes there at startup (a TTL index on `expires_at`, one on `ns`), so the database user needs the right to create indexes; if that fails, the app starts anyway with a warning (an error, with the cause, for conflicting indexes, failed authentication or missing rights), and writes to the store fail until the indexes exist. Each start also tries to cut the expiry of existing entries to the current `max_ttl`; if that fails (logged), they keep their expiry until a later start succeeds. Without database, each process keeps its entries in memory, without size limit (configure a short `max_ttl`), and the app warns at startup if plugins keep stored data there. Plugins that use `ctx.store` require `foca>=0.19` (#550, #557, #564, #568)
- Gateway plugins: plugins declare what they keep in their store (`data_stored`), and the plugin listing (`GET /plugins`, `GET /plugins/{plugin_id}`) shows it with the mode of the plugin's store (`storage`: `shared`, `local` or `off`); both fields are new and required (the listing's specification is now version 1.1.0), so clients that validate listings need to know them, and plugins that declare `data_stored` require `foca>=0.19` (#551, #560, #564, #568)
