FOCA 0.20.0 removes pip from the FOCA image, so that image scans of apps built on it no longer report the copies of packages that pip vendors, and closes a way for clients to overwrite records of failed runs. Gateway apps can key the hashes of the plugin store with a secret, and the Helm library chart foca-common 0.4.0 runs apps with several replicas and tunable probes. Apps whose images install packages with `pip install` on top of the FOCA image need to change, as do apps that read failure records by their `_id`: see the [migration guide](https://foca.readthedocs.io/en/v0.20.0/migration-0.20/). Token exchange is not part of this release.

## Breaking changes

- The FOCA image no longer contains pip, which vendors copies of other packages that image scans report in every image built on FOCA; `pip install` in a `Dockerfile` based on the image now fails, so install packages with uv from a pinned stage, without copying uv into the image, and remove the entries for pip's vendored packages from `.trivyignore.yaml` (#556, #592)
- Gateway plugins: records of failed runs (`ProvenanceStore.save_failure()`, only with `plugins.provenance.record_failed: true`) are keyed (`_id`) by `run-` and the server-generated run ID rather than the client's `X-Request-ID`, which stays in the field `request_id`; lookups by request ID need to query that field, and also `_id` while records of 0.19.0 exist (#575, #587)

## Features

- Gateway plugins: the setting `plugins.defaults.store.key_secret` or the environment variable `FOCA_PLUGINS_STORE_KEY_SECRET` keys the hashes of `ctx.store.key_for()` (HMAC-SHA256), and apps that keep such data in the database without it log a warning at startup; setting, changing or removing the secret makes entries keyed with `key_for()` unreachable (#565, #589)
- foca-common 0.3.0: app replicas (`replicas`) and a PodDisruptionBudget (`podDisruptionBudget`); app charts need a template file for the budget (#584, #585)
- foca-common 0.4.0: the value `pluginStore.existingSecret` passes the plugin store's key secret from an existing Secret to the app and the worker, and rendering fails if the config overlay sets it (#565, #589; #644, #650)
- foca-common 0.4.0: overrides of the app's probes (`startupProbe`, `readinessProbe`, `livenessProbe`) (#603, #642)

## Security

- Gateway plugins: clients can no longer overwrite records of failed runs, or collide with those of others, by reusing a request ID (#575, #587)
- `GuardedClient`: bodies of redirects are limited to `max_response_size` without reading them first, and `auth` or session hooks that read responses without limit (e.g., `HTTPDigestAuth`) are refused (#640, #643)
- Validation errors of the configuration no longer show the invalid input, including the plugins' `config` and step `params` and the custom configuration, as it may contain secrets (#565, #589; #646, #653)
- FOCA requires urllib3 2.8 (CVE-2026-97688, CVE-2026-97689, which defeat the deadline and size limit of `GuardedClient` against hostile servers) and pymongo 4.18.3 (CVE-2026-106435) (#645, #653)
- A warning at the first token validation names trusted issuers reached without TLS, except on the loopback interface (#647, #652)

## Fixes

- `GuardedClient` decides by whether sending has started if an error is `RequestNotSent` or `RequestMaybeSent`, not by the kind of error, so some errors change: see the migration guide (#640, #643)
- `GuardedClient` reports a header that can't be encoded as Latin-1 as `invalid_header`, not as `invalid_url` (#647, #652)
- foca-common: `requireAudience` accepts configurations in which each issuer has an `audience` of its own, as FOCA does (#604, #641)
- Access control logs the warning about group subjects at the right level, and the plugin listing has the right media type (#577, #639)
