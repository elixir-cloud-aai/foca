FOCA 0.22.0 prepares apps for FOCA's ASGI release, which moves to Connexion 3 `AsyncApp` and removes Flask and Flask-Cors. Nothing is removed in 0.22.0: FOCA warns about what the ASGI release removes where it can, and adds replacements that already work on Connexion 2: request and claims accessors (`foca.context`), framework-neutral errors (`foca.errors`), a test client (`foca.testing`) and an ast-grep rule that finds Flask imports. The functions that take a Flask app (`get_app_config()`, `set_app_config()`, `enable_cors()` and `foca.factories.celery_app.create_celery_app()`) emit a `DeprecationWarning`, and FOCA logs each deprecation once per process; exception maps with raw Werkzeug classes are logged as deprecated and stop working with the ASGI release. Move your app now: see [Preparing for the ASGI release](https://foca.readthedocs.io/en/v0.22.0/preparing-for-asgi/) and the [migration guide](https://foca.readthedocs.io/en/v0.22.0/migration-0.22/). When work on the ASGI release starts, a `0.22.x` branch is cut from the latest 0.22 release, for dependency and security fixes while apps migrate.

## Breaking changes

- Deprecated, removed in the ASGI release: `get_app_config()`, `set_app_config()`, `enable_cors()` and `foca.factories.celery_app.create_celery_app()` emit a `DeprecationWarning` and are logged once per process; use `foca.get_config()` (in scripts, with `Foca.use_config()`), the `security.cors` configuration and `Foca.create_celery_app()` instead (#637, #731, #741, #742)

## Features

- Responses to invalid requests list all invalid fields, of the body and the parameters together, in the new member `errors` of their problem details, with the problem type [Invalid request](https://foca.readthedocs.io/en/v0.22.0/problems/invalid-request/); `title`, `status` and `detail` stay as before. Raise `foca.errors.InvalidFieldsProblem` to list the invalid fields of checks of your own the same way (#586, #711, #712, #734)
- `Foca.use_config()` lets scripts use a configuration and its collections (`get_config()`, `get_collection()`) without creating an app, without Flask and without writing to the database; it replaces `set_app_config()` for scripts (see [Preparing for the ASGI release](https://foca.readthedocs.io/en/v0.22.0/preparing-for-asgi/#configuration)) (#741, #742)

## Security

- Responses to invalid requests no longer quote the rejected values (and, for parameters, the schema) in `detail`, which now names the invalid fields by location and code, e.g., `Invalid fields: #/name (too-long)`; they stay listed in `errors`. Set the new option `exceptions.validation_reasons: true` to keep the validator's reasons, e.g., if clients depend on them (#732, #733, #736, #738)
- The plugin gateway's refusals of per-request pipelines and backends no longer quote the client's values; they name fields, settings and the positions of steps, e.g., `Plugin not available in step 1` (see [Plugin gateway messages](https://foca.readthedocs.io/en/v0.22.0/migration-0.22/#plugin-gateway-messages)) (#739, #740)

## Fixes

- Apps are released when they are no longer used, also while objects of their APIs live on, e.g., in log records that a handler keeps; before, such objects kept the Flask app alive, which mattered for processes that build many apps, such as test suites (#735, #737)

## Documentation

- New page [Preparing for the ASGI release](https://foca.readthedocs.io/en/v0.22.0/preparing-for-asgi/): what the ASGI release removes, what to use now, with examples, and how to find what is left (#637, #731)
